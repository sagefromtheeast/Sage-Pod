Security policy

Found a security problem? Tell us privately.

Sage Pod reads feeds, audio and show notes from servers it doesn't control. If one of them can make the app misbehave, we want to hear about it before anyone else does.

Email a security report Or report it on GitHub

Reporting a problem

Please don't open a public issue for a security problem.

Report it privately through GitHub: on the repository's Security tab, choose Report a vulnerability. If that isn't available, email faithsoul.feed@gmail.com with "Sage Pod security" in the subject.

Please include:

  • what an attacker could do, and what they need (a malicious feed, a link, a position on the network, physical access…)
  • steps or a sample feed that reproduce it
  • the app version (Settings › About) and your device

You'll get a reply within a week. Fixes ship as a normal release, and you're credited in the release notes unless you'd rather not be.

Supported versions

Only the latest release gets security fixes: the newest tag on main, and the newest build on Google Play.

What is in scope

Problems in how the app handles content from podcast feeds, episode files, artwork, chapter files and show-note links. For example:

  • a feed, chapter file or show note that crashes the app, runs script, or reads or writes files outside the app's storage
  • feed passwords leaking: logged, sent to another host, or sent over plain HTTP
  • a link (itpc://, podcast://, sagepod://…) that does more than open a screen
  • a backup file that does more than restore the app's own data

Out of scope: the security of podcast hosts themselves, the content of podcasts, and attacks that need a rooted or jailbroken device.

How the app protects you

  • Feed passwords live in the system keystore and are sent only to the feed's own host. They are never sent after a redirect to another host, or from HTTPS down to HTTP.
  • Plain HTTP is allowed because many podcast feeds and audio files are still served over it. HTTPS is used whenever a feed offers it.
  • Show notes are shown as text and links, never in a web view, so a feed can't run script inside the app.
  • The app has no server and no account, so there's no store of user data anywhere else to breach.
